IMPADOC · Frontend

Formato
Consumo

Aplicación React para gestionar entregas operativas, planes anuales de consumo, inventario, solicitudes con flujo de aprobación, homologación del histórico Excel y un panel operativo centralizado.

React 18 + Vite 5
Backend: Laravel API
Empresa: Impadoc S.A.
Contexto

¿De qué trata el programa?

📦

Problema que resuelve

Centraliza el control de productos de aseo y consumibles: quién recibe qué, cuánto hay en stock, qué se pidió vs. qué se consumió históricamente, y cómo homologar datos del Excel legacy.

🎯

Para quién es

Personal operativo de almacén, supervisores que aprueban solicitudes, y administradores que gestionan inventario, precios históricos y el histórico Excel promovido.

🔗

Arquitectura

Frontend SPA en React consume una API REST Laravel (Sanctum). El frontend muestra datos y formularios; las reglas de negocio (stock, estados, roles) las valida el backend.

📊

Referencia histórica

Parte de los datos provienen del Excel FORMATO CONSUMO Y PEDIDO PDTOS ASEO 2026.xlsx, homologado y promovido al sistema sin modificar el original.

Alerta si varía

🔄 Solicitud → Entrega vinculada

En una solicitud aprobada, el botón Registrar entrega abre el tab de Entregas con el solicitud_id prellenado (Block 6.4).

📈 Semáforo de consumo (Block 7)

Compara consumo del mes vs. promedio histórico. Verde / amarillo / rojo. Botón Generar alertas del mes evalúa variaciones (requiere login).

💰 Precios históricos (Block 8)

Precio unitario automático en solicitudes. Botón Sugerir dinero del mes en consumo anual = cantidad × precio vigente.

📋 Homologación Excel (Block 6.5)

Datos del Excel entran a staging → homologación manual o masiva → validación → promoción al histórico oficial (Block 4 protegido).

Seguridad

Autenticación y permisos

Login mínimo (Block 6.2)

Botón Ingresar en navbar → modal de login.
Token en localStorage.auth_token.
Enviado como Authorization: Bearer en cada petición.
Servicio: authService.js

  • ✓ Crear, aprobar, rechazar o cancelar solicitudes

  • ✓ Homologar, validar y promover staging histórico
  • ✓ Generar alertas del semáforo de consumo
  • ✓ Registrar precios históricos

Equipo

Reglas del equipo

  • 1 El backend valida stock, unidades y estados — el frontend no duplica esas reglas de negocio.
  • 2 No modificar datos del Block 4 (histórico Excel promovido) sin autorización explícita.
  • 3 Productos 2 y 28: inventario real protegido — no usar en pruebas destructivas.
  • 4 No ejecutar seeders ni operaciones POST/PUT/PATCH/DELETE contra la BD real sin autorización.
  • 5 Para probar auth en local: UserSeeder en backend → solicitante@impadoc.test / password
